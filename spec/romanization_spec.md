# ローマ字入力判定仕様書

## 1. 概要
本仕様書は、ゲーム内で日本語（お題）をローマ字で入力する際の判定ルールを定義します。
プレイヤーが不条理な入力エラー（Typo扱い）でストレスを感じないよう、一般的かつ柔軟なローマ字入力を許容する判定システムを設計します。

## 2. 大文字・小文字の不問（ケースインセンシティブ）
プレイヤーの入力は、**大文字・小文字を完全に同一視**して判定します。
*   キーボードの「Caps Lock」や、シフトキーの押しっぱなし等による意図しない大文字入力であっても、正常に入力されたものとして扱います。
*   **例**: お題のローマ字が `ringo` の場合、`RINGO`、`Ringo`、`rInGo` などの入力はすべて正解として判定されます。

## 3. 複数入力パターンの許容ルール（重要）
特定のひらがなに対して、複数のキー入力をすべて正解として認めます。

### 代表例（ユーザー要件）
*   「ん」＋「ご」の組み合わせにおける、撥音（ん）の許容：
    *   **パターンA（標準）**: `ringo`（nの後ろがgなどの子音であるため、nが1つでも「ん」として機能する）
    *   **パターンB（厳密）**: `rinngo`（nを2回入力する「ん」の入力方法）
    *   **判定**: システムは `ringo`、`rinngo` のどちらの入力でも正解として受け入れます。

### その他の主要な複数許容ルール
開発時に実装モデルがカバーすべき主要な変換候補表です。

| ひらがな | 許容キーパターン | 備考 |
| :--- | :--- | :--- |
| **し** | `si`, `shi` | |
| **ち** | `ti`, `chi` | |
| **つ** | `tu`, `tsu` | 「つつまれる」などの連続した「つ」は `tutumareru`、`tsutsumareru`、`tsutumareru`、`tutsumareru` すべてを許容します。 |
| **じ** | `zi`, `ji` | |
| **ふ** | `hu`, `fu` | 「ふせぐ」は `fusegu`、`husegu` いずれも許容されます。 |
| **しゃ** | `sya`, `sha` | しょ（syo, sho）等も同様 |
| **ちゃ** | `tya`, `cha` | ちょ（tyo, cho）等も同様 |
| **じゃ** | `zya`, `ja` | じょ（zyo, jo）等も同様 |
| **うぉ** | `uxo`, `who` | 小さい文字単体の入力も考慮 |
| **ん** | `nn`, `n` | 文末や、次に母音・ヤ行が来る場合は `nn` 必須。それ以外は `n` も許容。 |
| **ー（長音記号）** | `-` | 「オーク」は `o-ku` と表記（`ooku` や `owoku` などは不可、必ずハイフンを使用）。 |

## 3. 入力判定エンジンの設計アプローチ（開発用参考）
本仕様を実現するために、実装AIまたはエンジニアは以下のいずれかのアプローチを採用します。

### アプローチ1: 状態遷移マシンの自動生成（推奨）
1.  日本語（お題）を受け取り、対応するすべての有効なローマ字キーストロークのパス（非決定性有限オートマトン: NFA）を内部的に構築します。
2.  プレイヤーがキーを押すたびに、現在の入力状態から遷移可能なパスを進めます。
3.  例えば「りんご」の場合：
    *   `r` -> `i` まで入力した時点で、次は `n` または `n` -> `n` の分岐が発生します。
    *   `n` が押された時：
        *   次のキーが `g` なら、最初の `n` は「ん」として確定し、`g` -> `o` と進めます。
        *   次のキーが `n` なら、`n` -> `n` で「ん」が確定し、さらに `g` -> `o` と進めます。

### アプローチ2: 事前キーマップ分割
1.  お題のひらがなを「音節（シラブル）」単位に切り分けます。
    *   例：「りんご」 ＝ 「り」 ＋ 「ん」 ＋ 「ご」
2.  各音節の許容ローマ字リストをマッピングします。
    *   「り」 ＝ `["ri"]`
    *   「ん」 ＝ `["n", "nn"]`
    *   「ご」 ＝ `["go"]`
3.  プレイヤーのリアルタイム入力を文字列前方一致で照合し、いずれかの有効なルートに合致しているかを判定します。
